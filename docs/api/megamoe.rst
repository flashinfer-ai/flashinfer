flashinfer.megamoe
==================

.. currentmodule:: flashinfer.megamoe

SM90 W4A8 expert-parallel MegaMoE with NVFP4 fused/split and MXFP4 fused kernels.
All paths use FP8 E4M3 activations and return BF16 outputs. Execution requires
NVLink-connected Hopper GPUs within each node and a symmetric buffer allocated
collectively before CUDA graph capture. NVFP4 supports four or eight ranks on
one node. MXFP4 supports power-of-two rank counts from one to 32, including
multiple nodes through :class:`MegaMoENcclTransport`. The inter-node path needs
NCCL device API headers and a GIN-capable NCCL installation; set ``NCCL_HOME``
when these are not provided by the ``nvidia-nccl`` wheel.

Replica plan (MXFP4)
--------------------

Redundant expert slots per rank, the plan tables that route each logical
expert's token blocks onto its copies, and the weight copy of the slots whose
expert changed, either as a separate kernel or inside the MXFP4 fused kernel.
Replica planning and fused weight copies currently require one node and the
default MXFP4 weight storage.

EP8 and EP16 reproduction
------------------------

The ``flash`` preset represents the routed MoE core used in the DeepSeek V4
Flash measurements, with the following layer dimensions:

.. list-table:: Tested MoE layer
    :header-rows: 1
    :widths: 40 60

    * - Parameter
      - Value
    * - Hidden width (H)
      - 4096
    * - Expert intermediate width (I)
      - 2048
    * - Routed experts (E) / selected experts per token
      - 256 / 6
    * - FC1 / FC2 weight shape per expert
      - [4096, 4096] / [4096, 2048]
    * - Weight values / activations / output
      - MXFP4 / FP8 E4M3 with FP32 scales / BF16
    * - Experts per rank at EP8 / EP16
      - 32 / 16
    * - Deployment
      - 1 x 8 H20 / 2 x 8 H20

The same public kernel API and benchmark support one-node EP8 and two-node
EP16. The benchmark times routed experts, including dispatch and combine;
router, shared experts and input quantization are outside the timed region.
Weights are generated by global expert ID and inputs by global token ID so
equal-total-token runs use the same logical workload. JSON output retains
all rank samples and input identities; CSV includes both per-rank and total
token counts. ``median_us`` is the median of the slowest rank in each sample;
``max_rank_median_us`` is the largest of the rank medians.
With equal tokens per rank, aggregate throughput speedup is
``2 * EP8_latency / EP16_latency`` and per-GPU throughput speedup is
``EP8_latency / EP16_latency``. With equal total tokens, latency and aggregate
throughput speedup are both ``EP8_latency / EP16_latency``; the per-GPU
throughput speedup is half that value.

On one host with eight H20 GPUs::

    torchrun --standalone --nproc-per-node=8 benchmarks/bench_megamoe_fp4_sm90.py \
      --shapes flash --tokens 1 4 8 16 32 64 --repeats 200 --rounds 5 \
      --output ep8.json --csv ep8.csv

On each of two hosts, set the same ``MASTER_ADDR`` and ``MASTER_PORT`` and a
different ``NODE_RANK`` (0 or 1)::

    torchrun --nnodes=2 --nproc-per-node=8 --node-rank="$NODE_RANK" \
      --master-addr="$MASTER_ADDR" --master-port="$MASTER_PORT" \
      benchmarks/bench_megamoe_fp4_sm90.py --shapes flash \
      --tokens 1 4 8 16 32 64 --repeats 200 --rounds 5 \
      --output ep16.json --csv ep16.csv

For an equal-total-token comparison, pass ``--token-scope total`` and
``--tokens 16 64 128 256 512 1024`` on both runs. Specify customer dimensions
with ``--hidden H --intermediate I --experts E --topk K`` in place of
``--shapes flash``. The default weight storage is ``mxfp4``; explicit
``--weight-storage mxfp4_compact`` or ``--weight-storage fp8`` selects the
corresponding prepared layout. These optimized layouts currently target
H20 with E256/H4096/I2048/top-6 and reject unsupported batch/format plans.

Run the independent dense-reference and CUDA Graph checks with the same
``torchrun`` topology before collecting timings::

    torchrun --standalone --nproc-per-node=8 \
      tests/moe/test_megamoe_mxfp4_transport_sm90.py \
      --hidden 4096 --intermediate 2048 --experts 256 --topk 6 \
      --tokens 1 4 8 16 32 64

For EP16, replace the launcher with the two-node command above. Cross-node
tests automatically use NCCL windows and skip the single-node transport pair.
Pass the same ``--weight-storage`` to validation and timing.
