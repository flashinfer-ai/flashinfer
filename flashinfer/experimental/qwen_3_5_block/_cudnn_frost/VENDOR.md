## How to re-vendor
The exporter and its inputs live next to this tree in `flashinfer/experimental/qwen_3_5_block/_vendoring/` (`vendor.py`, `closure.json`, `nanobind_enums.json`, `build_closure.py`, `trace_closure.py`, a README with the recipe):
```
python flashinfer/experimental/qwen_3_5_block/_vendoring/vendor.py --fe <cudnn_frontend checkout> --commit <new commit> --target <flashinfer>/flashinfer/experimental/qwen_3_5_block/_cudnn_frost --package flashinfer.experimental.qwen_3_5_block._cudnn_frost --selftest
```
`closure.json` (the closure list: every file, its module, licence and the digest of its blob at the pinned commit) is produced by `build_closure.py` from the import traces of `trace_closure.py` (run on a host for the declarations and on a cc 10.7 device for compile + execute of each form); a re-vendor at a new commit re-runs `vendor.py` alone when the route is unchanged (the exporter stops on any blob whose digest moved: recompute the closure then), and re-runs the tracer + builder when the FE route changes (a new kernel file, a new lazily imported module).  The self-test must pass before the vendored tree is committed; the FlashInfer test `test_support.py` re-digests every file against `VENDOR_MANIFEST.json`.
