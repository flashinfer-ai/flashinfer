## How to re-vendor
The exporter and its inputs live next to this tree in `flashinfer/experimental/qwen_3_5_block/_vendoring/` (`vendor.py`, `closure.json`, `nanobind_enums.json`, `build_closure.py`, `trace_closure.py`, a README with the recipe):
```
python flashinfer/experimental/qwen_3_5_block/_vendoring/vendor.py --fe <cudnn_frontend checkout> --commit <new commit> --target <flashinfer>/flashinfer/experimental/qwen_3_5_block/_cudnn_frost --package flashinfer.experimental.qwen_3_5_block._cudnn_frost --selftest
```
`closure.json` (the closure list: every file, its module, licence and the digest of its blob at the pinned commit) is produced by `build_closure.py` from the import traces of `trace_closure.py` (run on a host for the declarations and on a cc 10.7 device for compile + execute of each form); a re-vendor at a new commit re-runs `vendor.py` alone when the route is unchanged (the exporter stops on any blob whose digest moved -- the FE test-tree file `sdpa/fwd/_binding_reference.py` included, pinned in `closure.json`'s `extra_files`: re-check the Python binder against it, then recompute the closure), and re-runs the tracer + builder when the FE route changes (a new kernel file, a new lazily imported module).  The self-test must pass before the vendored tree is committed; the FlashInfer test `test_support.py` re-digests every file against `VENDOR_MANIFEST.json`.

The shim provides the enums, `cudnnGraphNotSupportedError`, `make_operand_buffer` and `WorkspaceCarve` in Python, and the SDPA binders' `supports_*` capability flags; `backend_graph` / `create_handle` / `get_stream` are unreachable under P1.  The SDPA LAUNCH binders (`_SdpaDenseBinder`, `_SdpaThdBinder`, `_read_buffer_sequence`, `_native_pack_from_facts`) are served IN PYTHON by `flashinfer.experimental.qwen_3_5_block._sdpa_binder` (imported on first use), which builds on `sdpa/fwd/_binding_reference.py` -- cuDNN Frontend's own retired Python frame implementation of the binder, vendored byte-faithfully from the FE test tree (`test/python/sdpa/frost/sdpa_binding_reference.py`, MIT) -- and adds the operand pack and the THD epilogue-gate arm that file predates.  It is the explicit, documented and only binder of this tree (never a silent fallback), for the half (bf16 / f16) plans; a quantized plan is a typed decline, and so is a SPLIT plan with an attention sink: the extension's dense binder appends the fp32 sink pointer and, over padded query lengths, the per-batch Q-length address to the combine frame (`DenseLaunchSpec.combine_q_lens`), the Python binder binds neither and the shim's `_SdpaDenseBinder.supports_combine_q_lens` reads False for it (`PYTHON_BINDER_FLAGS` in `vendor.py`), so the vendored `prepared.py` declines such a plan by name before it is built; on cc 10.7 the adapter never splits a dense plan with a sink, so the decline is unreachable on the served device.  The extension's sources, for a native binder later: `python/pygraph/{variant_pack.cpp,variant_pack.h,sdpa_dense_binding.cpp,sdpa_thd_binding.cpp,sdpa_fixed_binding.h,sdpa_mxfp8_binding.h}` (nanobind + dlpack only, no cuDNN headers).
